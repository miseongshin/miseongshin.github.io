의견

사용자 흐름

로그인
회원가입 / 로그인 → Google → 닉네임(비우면 자동 생성) → 내 정보 입력 → 가입 완료
조회
메인 → 검색 · 탭 · 순위 → 상세 → 관련 고민 · 생각 · 활동 → 상세. 로그인 없이 볼 수 있다.
작성
작성 버튼 → (비로그인이면 로그인) → 작성 팝업 → 등록 → 해당 상세
꿀팁 나눔
고민 상세 → 이 고민에 꿀팁 나눔 → 고민이 채워진 작성 팝업 → 등록 → 고민 상세
스케줄
활동 · 생각 · 스케줄 담기 → 활동바구니 → 스케줄 등록 → 활동별 요일 → 등록 → 스케줄 상세
수정 · 숨김
내 계정 또는 상세 → 수정 → 작성 팝업 → 저장 / 공개 ↔ 숨김
반응
상세 → 좋아요 · 댓글 · 활동완료 (로그인 필요)
탈퇴
내 계정 → 내 정보 수정 → 맨 아래 탈퇴 → 확인

3.데이터 설계

ERD

1. 주요기능(고민, 활동, 스케줄)

  • 고민에 생각꿀팁, 활동꿀팁이 1:N 관계로 작성할 수 있다.
  • 꿀방울 스케줄은 고민과 별도로 작성되고 태그로 연결된다.
erDiagram
  member ||--o{ thought_tip : "생각꿀팁 등록"
  thought_tip ||--o{ thought_tip_url : "링크를 붙인다"
  worry |o--o{ thought_tip : "고민에 답한다 (worry_id)"
  member ||--o{ worry : "고민 등록"
  worry ||--o{ activity_tip : "활동꿀팁 · 도움이 된 활동"
  activity ||--o{ activity_tip : "고민에 추천된다"
  activity ||--o{ activity_url : "활동에 영상·링크를 붙인다"
  activity }o--o| mission : "미션에 속한다"
  member |o--o{ activity : "활동 등록"
  activity ||--o{ schedule_activity : "스케줄에 들어간다"
  schedule ||--o{ schedule_activity : "활동을 넣는다"
  member ||--o{ schedule : "스케줄 등록"

  member["member · 회원"] {
    bigint member_id PK "기본키"
  }
  worry["worry · 고민"] {
    bigint worry_id PK "기본키"
    bigint member_id FK "NOT NULL"
    varchar lang "언어 · 한국어(ko) 영어(en) …"
    varchar text "고민"
    boolean is_anonymous "익명 여부"
    varchar status "공개(PUBLIC) · 숨김(HIDDEN)"
    timestamptz hidden_at "숨긴 때"
    varchar hidden_reason "숨긴 이유 (예: AI: 광고)"
    int like_count "좋아요 수"
    int answer_count "답 수 · 답을 기다리는 고민 = 0"
    boolean show_tags "등록할 때 선택 · 글에 내 태그 보이기"
    timestamptz created_at "등록일"
    timestamptz updated_at "수정일"
  }
  thought_tip["thought_tip · 생각꿀팁"] {
    bigint thought_tip_id PK "기본키"
    bigint member_id FK "쓴 사람"
    bigint worry_id FK "답한 고민 · 없으면 NULL"
    text body "도움이 된 생각"
    varchar lang "언어"
    varchar status "공개(PUBLIC) · 숨김(HIDDEN)"
    timestamptz hidden_at "숨긴 때"
    varchar hidden_reason "숨긴 이유 (예: AI: 광고)"
    int like_count "좋아요 수"
    boolean show_tags "등록할 때 선택 · 글에 내 태그 보이기"
    timestamptz created_at "등록일"
    timestamptz updated_at "수정일"
  }
  thought_tip_url["thought_tip_url · 참고 링크"] {
    bigint link_id PK "기본키"
    bigint thought_tip_id FK "생각꿀팁"
    varchar url "주소 · 유튜브면 바로 재생"
    timestamptz created_at "등록일"
    timestamptz updated_at "수정일"
  }
  schedule["schedule · 꿀방울 스케줄"] {
    bigint schedule_id PK "기본키"
    bigint member_id FK "쓴 사람"
    varchar title "스케줄 이름"
    text description "설명 · 선택"
    varchar lang "언어"
    varchar status "공개(PUBLIC) · 숨김(HIDDEN)"
    timestamptz hidden_at "숨긴 때"
    varchar hidden_reason "숨긴 이유 (예: AI: 광고)"
    int like_count "좋아요 수"
    int send_count "사용자 수"
    boolean show_tags "등록할 때 선택 · 글에 내 태그 보이기"
    timestamptz created_at "등록일"
    timestamptz updated_at "수정일"
  }
  activity_tip["activity_tip · 활동꿀팁"] {
    bigint activity_tip_id PK "기본키"
    bigint worry_id FK "고민"
    bigint activity_id FK "활동"
    bigint member_id FK "추천한 사람"
    timestamptz created_at "등록일"
    timestamptz updated_at "수정일"
  }
  schedule_activity["schedule_activity · 스케줄 구성"] {
    bigint schedule_id PK, FK "기본키"
    bigint activity_id PK, FK "기본키"
    varchar days "요일 · 월0 화1 수2 목3 금4 토5 일6 · 예 0,3 = 월·목 · 비우면 매일"
    timestamptz created_at "등록일"
    timestamptz updated_at "수정일"
  }
  mission["mission · 미션"] {
    varchar code PK "기본키"
    boolean fixed "고정"
    timestamptz created_at "등록일"
    timestamptz updated_at "수정일"
  }
  activity["activity · 활동"] {
    bigint activity_id PK "기본키"
    varchar mission_code FK "미션"
    varchar name "이름"
    text description "설명"
    bigint created_by FK "등록한 사람"
    varchar status "공개(PUBLIC) · 숨김(HIDDEN)"
    timestamptz hidden_at "숨긴 때"
    varchar hidden_reason "숨긴 이유 (예: AI: 광고)"
    int use_count "사용자 수"
    int done_count "활동 수"
    int like_count "좋아요 수"
    timestamptz created_at "등록일"
    timestamptz updated_at "수정일"
  }
  activity_url["activity_url · 활동 영상·글"] {
    bigint activity_url_id PK "기본키"
    bigint activity_id FK "활동"
    varchar url "주소"
    timestamptz created_at "등록일"

3. 댓글, 좋아요

  • 댓글은 활동, 꿀방울 스케줄 상세화면에서 사용한다.
  • 좋아요는 고민 · 생각꿀팁 · 스케줄 · 활동 네 곳에 누를 수 있다.
erDiagram
  activity |o--o{ comment : "활동 댓글"
  schedule |o--o{ comment : "스케줄 댓글"
  member ||--o{ comment : "댓글을 쓴다"
  member ||--o{ likes : "좋아요를 누른다"

  comment["comment · 댓글"] {
    bigint comment_id PK "기본키"
    bigint activity_id FK "활동 · 둘 중 하나만"
    bigint schedule_id FK "스케줄 · 둘 중 하나만"
    bigint member_id FK "쓴 사람"
    varchar text "내용"
    timestamptz created_at "등록일"
  }
  likes["likes · 좋아요"] {
    bigint like_id PK "기본키"

    varchar target_type "고민(WORRY) · 생각꿀팁(THOUGHT_TIP) · 스케줄(SCHEDULE) · 활동(ACTIVITY)"
    bigint target_id "대상 번호"
    timestamptz created_at "등록일"
    timestamptz updated_at "수정일"
  }

  • 앱 로그(활동완료 · 도움돼요)는 꿀방울앱에서 활동, 도움되요 클릭시 전송된다.

  member ||--o{ member_nickname_history : "닉네임을 바꾸면 남긴다"

    varchar app_key UK "앱 키 · 누구인지"

    timestamptz created_at "등록일"
    timestamptz updated_at "수정일"
  }
  member_nickname_history["member_nickname_history · 닉네임 백업"] {
    bigint nickname_history_id PK "기본키"
    bigint member_id FK "회원"
    varchar nickname "바꾸기 전 닉네임"
    timestamptz changed_at "바꾼 때"

  }

  • 검증 Authorization: Bearer <앱 키> · 해시로 비교 · 틀리면 401 · 로그인 없음
  • 재발급 내 계정에서 다시 만들면 이전 키는 바로 막힌다
  • 보내기 바구니에 담기(cart) → 내 꿀방울로 보내기(sent_at) → 앱이 가져감(GET /app/takes) → 받았다고 알림(ack · picked_at) → 스케줄 send_count +1
  • 활동 완료 activityKey 로 활동을 찾아 app_done_log 에 저장 · 같은 활동은 하루 한 번
  • 도움됨 helpful true 켜기 · false 끄기 · app_helped_log

고민·생각꿀팁·활동·꿀방울 스케줄 처리

  • 고민 등록 시 바로 공개 · 50자 · 기본 익명 · 태그는 #으로 구분
  • 생각꿀팁 · 활동꿀팁 고민에 답한다 · 쓰면 고민의 answer_count +1 · 0 이면 답을 기다리는 고민
  • 활동 미션 선택 · 이름 · 시간 · 난이도 · 설명 · 영상 · 글 링크 여러 개 · 활동꿀팁에서 고르거나 새로 등록
  • 꿀방울 스케줄 바구니에 담은 활동으로 만든다 · 활동별 요일 설정가능
  • 수정 · 숨김 본인만 · 지우지 않고 HIDDEN · AI 검사나 관리자도 숨길 수 있다
  • 좋아요 한 사람이 한 번 · 누르면 likes 에 쌓고 수는 스케줄러가 1분마다 더한다

6.비기능 설계

보안

  • 통신: 모두 HTTPS. 세션 쿠키는 HttpOnly · Secure · SameSite=Lax.
  • 앱 키: 해시만 저장한다. 원래 값은 처음 만들 때 한 번만 보여 준다.
  • 작성: 고민 · 꿀팁 · 스케줄 · 댓글 · 좋아요 · 의견 모두 로그인 후. 보기는 로그인 없이. 모든 작성 테이블의 member_id 는 NOT NULL.
  • 삭제: 글쓴이만 지운다(소프트 삭제 deleted_at). 활동 · 스케줄은 댓글이 있으면 서비스에서 막는다 — 409.
  • 숨김: 등록 시 바로 공개. 저장 뒤 비동기로 AI 검사 → 문제 있으면 HIDDEN + hidden_at + hidden_reason "AI: 광고". 신고 · 관리자 화면에서 HIDDEN + hidden_reason "관리자: …".
  • 입력 검증: 요청 DTO 에 @Valid · 글자 수 제한 · 오류는 400.
  • 헬스 체크: Actuator 의 /actuator/health 만 연다(배포 확인 · 서버 감시). 설정값이 보이는 다른 Actuator 주소는 닫는다.

성능·페이징

  • 목록: OFFSET 대신 커서(마지막으로 본 id 이후)로 가져온다.
  • 색인: worry (status, answer_count, created_at) · thought_tip (status, created_at) · thought_tip (worry_id) · schedule (status, created_at) · likes 는 (target_type, target_id) · 태그 연결 테이블은 PK (대상_id, tag_id) + 역색인 (tag_id, 대상_id).
  • N+1: 목록은 fetch join · @EntityGraph · batch_fetch_size.

대용량 기준

  • 테이블 나누기: 고민(worry) · 생각꿀팁(thought_tip) · 스케줄(schedule)을 따로 둔다. 화면에서 쓰는 칸이 달라서다. 생각꿀팁만 worry_id FK 로 고민을 가리킨다.
  • 숫자: 좋아요 · 사용자 수 · 활동 수 · 태그 쓴 횟수는 누를 때 올리지 않는다. 원본(likes · app_done_log · cart · ○○_tag)에 쌓기만 하고, @Scheduled 스케줄러가 새로 쌓인 것만 세어 *_count 에 한 번에 더한다(좋아요 1분 · 나머지 1시간). 인기 글에 몰려도 줄 잠금이 없다.
  • 활동완료: app_done_log 은 가장 빨리 커진다. 월별 파티션 · '사용자 N명 · 활동 N회'는 activity 의 use_count · done_count 를 읽는다.
  • 많이 찾는 상황: worry_tag 를 매번 GROUP BY 하지 않고 몇 분마다 계산해 저장한다.
  • 보내기: cart 는 앱이 가져갈 때(ack) schedule.send_count 를 1 올리고, 가져간 줄은 다음 날 지운다.

화면 Nuxt 3 · 서버 Spring Boot + JPA상세 주소를 쇼핑몰처럼 정리하고 검색에 걸리게(SSR) · 백엔드 포트폴리오는 JPA 중심
로그인은 구글만외국 사용자도 쓸 수 있음 · 비밀번호를 받지 않아 관리할 것이 적음
웹은 세션 쿠키같은 도메인 · 서버 하나 · 로그아웃과 만료가 간단
앱은 Bearer 앱 키앱에 로그인 화면이 없어도 됨 · 서버는 해시만 저장
승인 없이 등록 시 바로 공개운영자 1명 · 사용자가 기다리지 않음 · 문제 글은 AI 검사와 관리자가 숨김
태그는 @ManyToMany + @JoinTable연결 테이블에 추가 칸이 없어 엔티티가 필요 없음
목록은 커서 페이징글이 많아져도 OFFSET 처럼 느려지지 않음
숫자는 스케줄러가 모아서 더함인기 글에 좋아요가 몰려도 줄 잠금이 없음
활동바구니는 로그인 후 cart 에 저장PC 에서 담고 앱으로 보내기 위해
