사용자 흐름

로그인
회원가입 / 로그인 → Google → 닉네임(비우면 자동 생성) → 내 정보 입력 → 가입 완료
조회
메인 → 검색 · 탭 · 순위 → 상세 → 관련 고민 · 생각 · 활동 → 상세. 로그인 없이 볼 수 있다.
작성
작성 버튼 → (비로그인이면 로그인) → 작성 팝업 → 등록 → 해당 상세
꿀팁 나눔
고민 상세 → 이 고민에 꿀팁 나눔 → 고민이 채워진 작성 팝업 → 등록 → 고민 상세
스케줄
활동 · 생각 · 스케줄 담기 → 활동바구니 → 스케줄 등록 → 활동별 요일 → 등록 → 스케줄 상세
수정 · 숨김
내 계정 또는 상세 → 수정 → 작성 팝업 → 저장 / 공개 ↔ 숨김
반응
상세 → 좋아요 · 댓글 · 활동완료 (로그인 필요)
탈퇴
내 계정 → 내 정보 수정 → 맨 아래 탈퇴 → 확인

3. 댓글, 좋아요

  • 댓글은 활동 · 꿀방울 스케줄 상세 화면에서 작성한다. 활동 · 스케줄을 숨기면 그 댓글도 보이지 않는다.
  • 좋아요는 고민 · 생각꿀팁 · 스케줄 · 활동 · 댓글에 누를 수 있다.
  • 신고는 고민 · 생각꿀팁 · 스케줄 · 활동 · 댓글에 할 수 있다. 같은 글에 3명 이상 신고하면 관리자에게 메일을 보낸다.

앱 키 검증 및 앱 연동

  • 앱 키 앱이 처음 실행할 때 받는다 · 웹 계정 없이 앱만 써도 활동 기록이 쌓인다
  • 연결 앱이 보여 준 연결 코드를 웹 내 계정에 넣으면 그 회원과 이어진다 · 기록은 옮기지 않고 member_app_key.member_id 만 채운다
  • 검증 X-App-Key (cart · 웹 바로 들어가기는 + 비밀값) · 틀리면 401 · 로그인 없음
  • 보내기 바구니에 담기(cart) → 내 꿀방울로 보내기(sent_at) → 앱이 받음(GET /app/takes) → 저장을 마치면 알림(ack · cart_id) → 그 행을 지우고 스케줄 send_count +1
  • 활동 완료 activityKey 로 활동을 찾아 app_done_log 에 저장 · 같은 활동은 하루 한 번
  • 도움됨 helpful true 켜기 · false 끄기 · 지우지 않고 app_helped_log 에 쌓는다 · 같은 상태가 두 번 오면 넣지 않는다

고민·생각꿀팁·활동·꿀방울 스케줄 처리

  • 고민 등록 시 바로 공개 · 50자 · 기본 익명 · 태그는 #으로 구분
  • 생각꿀팁 · 활동꿀팁 고민에 답한다 · 쓰면 고민의 answer_count +1 · 0 이면 답을 기다리는 고민
  • 활동 미션 선택 · 이름 · 시간 · 난이도 · 설명 · 영상 · 글 링크 여러 개 · 활동꿀팁에서 고르거나 새로 등록
  • 꿀방울 스케줄 바구니에 담은 활동으로 만든다 · 활동별 요일 설정가능
  • 수정 · 숨김 본인만 · 지우지 않고 HIDDEN · AI 검사나 관리자도 숨길 수 있다
  • 좋아요 한 사용자는 대상마다 한 번만 누를 수 있다 · 누르면 honey_like 에 저장하고, 취소하면 그 행을 지운다 · 좋아요 수는 스케줄러가 1분마다 honey_like 행을 대상별로 다시 세어 맞춘다 (1분 동안은 실제 좋아요 수와 다를 수 있다)

6.비기능 설계

보안

  • 통신: 모두 HTTPS. 세션 쿠키는 HttpOnly · Secure · SameSite=Lax.
  • 앱 키: 해시만 저장한다. 원래 값은 처음 만들 때 한 번만 보여 준다.
  • 작성: 고민 · 꿀팁 · 스케줄 · 댓글 · 좋아요 · 의견 모두 로그인 후. 보기는 로그인 없이. 모든 작성 테이블의 member_id 는 NOT NULL.
  • 삭제: 지우지 않고 숨긴다(status HIDDEN · hidden_reason 에 '본인 삭제' 처럼 누가 · 왜). 작성자 · 운영자만. 활동 · 스케줄은 댓글이 있어도 지울 수 있다 — 그 댓글은 같이 안 보인다.
  • 숨김: 등록 시 바로 공개. 저장 뒤 비동기로 AI 검사 → 문제 있으면 HIDDEN + hidden_at + hidden_reason "AI: 광고". 신고 · 관리자 화면에서 HIDDEN + hidden_reason "관리자: …".
  • 입력 검증: 요청 DTO 에 @Valid · 글자 수 제한 · 오류는 400.
  • 헬스 체크: Actuator 의 /actuator/health 만 연다(배포 확인 · 서버 감시). 설정값이 보이는 다른 Actuator 주소는 닫는다.

성능·페이징

  • 목록: OFFSET 대신 커서(마지막으로 본 id 이후)로 가져온다.
  • 색인: honey_worry (status, answer_count, created_at) · honey_thought_tip (status, created_at) · honey_thought_tip (worry_id) · honey_schedule (status, created_at) · 외래키 칸(honey_worry · honey_thought_tip · honey_schedule 의 member_id, honey_activity_tip · honey_schedule_activity 의 activity_id) — PostgreSQL 은 FK 에 색인을 자동으로 만들지 않는다 · honey_like 는 (target_type, target_id) · honey_comment 는 (activity_id, created_at) · (schedule_id, created_at) · (member_id) · honey_complaint 는 (target_type, target_id) · 미처리만 (created_at) · app_helped_log 는 (app_key_id, activity_id, created_at) · 태그 연결 테이블은 PK (대상_id, tag_id) + 역색인 (tag_id, 대상_id).
  • N+1: 목록은 fetch join · @EntityGraph · batch_fetch_size.

대용량 기준

  • 테이블 나누기: 고민(honey_worry) · 생각꿀팁(honey_thought_tip) · 스케줄(honey_schedule)을 따로 둔다. 화면에서 쓰는 칸이 달라서다. 생각꿀팁만 worry_id FK 로 고민을 가리킨다.
  • 숫자: 좋아요 · 사용자 수 · 활동 수 · 도움돼요 수 · 태그 사용 횟수는 호출마다 수정하지 않는다 — 인기 글에 몰려도 로우 락(row lock)으로 기다리지 않게. 원본 테이블(honey_like · app_done_log · app_helped_log · ○○_tag)에 기록하고, @Scheduled 스케줄러가 원본을 다시 세어 *_count 를 맞춘다 — 집계 기준 시점을 따로 저장하지 않아 누락되거나 중복 집계될 가능성이 없다. 좋아요는 1분마다(1분 동안은 실제 좋아요 수와 다를 수 있다) · 사용자 수 · 활동 수 · 도움돼요 수는 1시간마다 활동별로(사용자 수는 앱 키를 겹치지 않게) · 태그 사용 횟수는 1시간마다 공개 글만(글을 숨기면 줄어야 해서). *_count 는 UPDATE 쿼리로 갱신한다 — 엔티티로 고치면 글의 수정일까지 바뀐다. 스케줄 사용자 수(send_count)는 앱이 받았다고 알릴 때(ack) 1 올린다.
  • 활동완료: app_done_log 은 가장 빨리 커진다. 지금은 일반 테이블(커지면 월별 파티션) · '사용자 N명 · 활동 N회'는 honey_activity 의 use_count · done_count 를 읽는다.
  • 많이 찾는 상황: honey_worry_tag 를 매번 GROUP BY 하지 않고 tag.use_count 를 읽는다(스케줄러가 1시간마다 세어 바꿈).
  • 보내기: cart 는 앱이 받았다고 알릴 때(ack) honey_schedule.send_count 를 1 올리고 그 행을 바로 지운다.
